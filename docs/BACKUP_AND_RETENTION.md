# 数据库备份、恢复与保留

## 在线备份

```sh
RUSTFRP_DB=/srv/rustfrp/rustfrp.db rustfrp-server backup /srv/backups/rustfrp-20261011.db
```

源文件必须存在，目标文件必须不存在（空文件也拒绝）。备份只读打开源库，不升级源库版本、不改变其 WAL 模式；源库可以由正在运行的 Controller 持续使用。输出是包含已提交 WAL 内容的单文件一致性快照，用 SQLite `VACUUM INTO` 生成，不直接拷贝 WAL 主文件。该机制的事务一致性与同步行为见 [SQLite 官方说明](https://www.sqlite.org/lang_vacuum.html)。

同目录 `.partial` 临时文件写完并同步后，用不覆盖目标的硬链接原子发布；失败清理临时文件。进程被突然终止时可能遗留 `.partial`，不得把它作为完成的备份。目的文件系统需支持硬链接；不支持时命令明确失败。POSIX 文件权限 0600；Windows 使用目标目录的 ACL，因此请放在仅运维账号可访问的目录中。

备份包含管理员密码哈希、设备公钥和会话等敏感运营数据，应按私有数据保存。本轮未增加 REST 下载数据库接口。

## 恢复流程

1. 在隔离环境打开快照，执行 `PRAGMA integrity_check` 和 `PRAGMA foreign_key_check`，核实管理员、设备与隧道数据；检查本机二进制是否支持快照的 schema 版本。
2. **停止 Controller**，确保其数据库连接及其他运维数据库进程都已关闭。保存当前主库、`-wal`、`-shm` 为一套回滚材料。
3. 在同一文件系统准备快照副本，设置仅运行账号可读写的权限。将现有主库及其 WAL/SHM 移入回滚目录，然后把快照副本替换到 `RUSTFRP_DB` 配置路径。不能把旧 WAL/SHM 留在恢复后的新主库旁边。
4. 启动 Controller，让已支持的迁移自动执行；验证登录、设备重连、隧道实际收发和审计。恢复备份不会恢复未随备份保存的 agent 私钥；现有客户端继续使用其各自的私有身份文件。
5. 若需回滚，再停止所有数据库使用进程，整套还原保存的主库与对应 WAL/SHM 后重启。

当前交付为备份 CLI + 经过测试的快照重新打开 / 迁移 + 停服恢复操作流程，不提供能覆盖正在运行数据库的自动 restore 命令。

## 有界保留清理

| 环境变量 | 默认 | 范围与含义 |
|---|---|---|
| `RUSTFRP_AUDIT_RETENTION_DAYS` | 90 | 0..3650；0 永久保留审计；严格早于 UTC 毫秒截止点才删除 |
| `RUSTFRP_CLEANUP_BATCH` | 500 | 1..1000；每轮每表删除上限 |

Controller 每分钟执行一轮：清理到期管理会话、到期接入令牌、超出保留期的审计。新索引使清理按到期时间取固定数量。没有把整表记录加载进内存，也没有循环把大量历史一次删完。

有删除时在同一事务追加 `maintenance.purge` 系统审计，仅记录数量与策略。审计插入失败时整轮删除回滚；数据库错误明确记录到日志。关闭服务后不再调度新的清理批次。活跃会话、未过期接入令牌、保留边界和未来时间的审计都保留。

**流量桶尚未实现**：这次只完成现有表的清理；未来流量保留与 M-09 一同交付，不能提前标记整个 SV-11 完成。

## 内存与验收

无新增运行时依赖：SQLite cache 仍封顶约 2 MiB，备份通过数据库引擎和磁盘，不在 Rust 中缓冲整个库；定时任务常驻只持有 Db/取消句柄/定时器，删除数量固定。在线备份 CLI 是单独的运维进程，不把备份数据装入常驻 Controller 堆。

测试覆盖：真实 WAL、只读 v2 源库不迁移、带引号与空格的路径、现有目标不覆盖、失败无发布物、0600、按批多轮、边界保留、配置超限、审计失败回滚、错误日志与取消；全栈冒烟对运行中的 Controller 执行备份，检查完整性、设备和隧道数据。

流量数据另由 5 秒采样任务维护：分钟桶与累计游标保留 7 天，每轮每表最多删除 2048 行，删除与 `maintenance.traffic` 审计共事务。数据采样与清理任何一步失败，游标和桶一起回滚，不确认最终样本；下一轮重试。
